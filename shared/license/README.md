# 共享授权模块

链接抽取工具和视频分发工具通过本地 Go module `replace` 引用这里，避免授权逻辑和加固修复分叉。Account、Product、Policy ID 与 Ed25519 公钥统一在 `config.go` 配置；客户端不包含管理员或产品令牌，只使用用户授权码。

## 验证与正常使用

- 已保存授权码时，每次启动联网验证；持续运行每 24 小时复核。手动激活、重新验证和解除授权立即联网。
- 每分钟及每次核心操作检查本地签名缓存、有效期和宽限截止时间，不因此额外联网。
- 只有网络错误、服务端暂时不可用或限流允许使用有效缓存；宽限从上次成功验证起最多 7 天，且不超过授权本身到期。
- 每次联网验证成功后读取机器策略；仅当 `requireHeartbeat` 为真才发送心跳，间隔为 `heartbeatDuration / 2`，最短 1 分钟。24 小时设置不改变后台要求的心跳频率。
- 两款工具使用相同机器指纹；保留 `material-picker:` 前缀，文本工具更名不会改变机器登记。同一授权码在同一电脑上只占一个设备名额。
- 两款工具各自保存授权码和缓存。设备登记被移除而授权本身仍有效时，保留授权码的另一款工具可能自动重新登记；换电脑前需要在两款工具中都解除授权。卖家收回授权应暂停授权本身。

## 无 Garble 时保留的保护

- 响应和离线缓存必须通过 Ed25519 签名校验；验证固定账户、本产品、本策略、本机指纹和随机 nonce，拒绝伪造响应与范围替换。
- 明确拒绝或签名异常后清除成功缓存，并保存拒绝记录，恢复旧 `license.json` 不能直接恢复离线授权。
- 使用服务器签名时间及进程内单调时钟；持久记录最高已使用时间，检测重启后的明显时钟回退。
- Windows 的 `license-state.bin` 使用当前用户 DPAPI 保护，不需要管理员权限或额外密码。
- 应用在 Go 后端检查核心操作，前端激活页面仅用于交互。正式构建即使误传 `devlicense` 也不能跳过授权。

这些措施提高修改和绕过成本，不能保证本机完全受攻击者控制时仍无法破解。离线宽限期间也不能即时收到后台暂停结果。

## 检查

在本目录执行 `go vet ./...` 和 `go test -race ./...`，覆盖签名、激活、到期、离线、缓存恢复、时间回退、并发及同机共用设备名额。Windows runner 上还会执行 DPAPI 的真实加解密回归。

可选的真实服务器签名检查：`KEYGEN_LIVE=1 go test . -run '^TestLiveSignature$' -v`。默认测试只使用本地模拟服务器，不占用客户设备名额。

## 锁屏密码（`applock`）

两款工具共用的 4 位数字锁屏密码放在子包 `applock` 里，和授权模块一起发布，不需要另外的 module。

- 状态保存在各自数据目录的 `lock.json`：随机盐、迭代次数和 PBKDF2-HMAC-SHA256 的结果，不保存密码本身。文件缺失或损坏视为没有开启，所以删除文件即可关闭。
- 连续输错 5 次后开始限次：等待时间从 30 秒起每次翻倍，最长 10 分钟；计数写入文件，重启不会清零。
- 忘记密码时用已保存的授权码重置（`ResetLockWithLicense`）。
- 这是遮挡用的锁，不加密数据文件。界面何时显示锁屏由前端决定。
